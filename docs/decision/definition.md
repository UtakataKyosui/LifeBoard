# 1. エグゼクティブサマリー

- MVPの中心は、生活習慣・定期的な家事・生活環境の維持・学習／自己改善の反復行動を管理すること。

- 行動の実施有無と数値実績を両方扱う。数値は「実施ごとに記録し、日単位で集計する」方式を決定。

- 個人の生活データの保存先は各ユーザー自身のNotionを基本方針とする。初期段階は個人接続で進め、一般公開時のOAuthは別工程。

# 4. ドメインモデル：確定した基本方針と暫定設計

| 概念                      | 責務                                             | 状態                |
|---------------------------|--------------------------------------------------|---------------------|
| Routine                   | 習慣／定期作業の定義、周期、目標、ライフサイクル | 採用方針            |
| ScheduleRule              | 毎日・曜日指定・週N回などの繰り返し条件          | 3方式は暫定採用案   |
| Occurrence                | 特定の実行期間／予定の識別                       | 原則算出は暫定      |
| ExecutionRecord           | 1回の実施事実（同日複数件可）                    | 決定                |
| Measurement               | 実施1回に紐づく数値と単位                        | 0～1件は暫定MVP制約 |
| OccurrenceOutcome         | 実施ではないスキップ・延期の判断                 | 分離を推奨、未承認  |
| DailySummary／Achievement | 日次集計と目標達成判定                           | 算出を推奨          |
| WorkContext               | 複雑な作業の目的・現在地・次の行動               | 採用方針            |

# 5. データ・計算のルール

| 区分     | ルール                                             | 判定               |
|----------|----------------------------------------------------|--------------------|
| 実施記録 | 同じ日に同一RoutineのExecutionRecordを複数登録可能 | 決定               |
| 評価分離 | 「行動したか」と「数値目標を達成したか」を分ける   | 合意済み方針       |
| 集計     | 実施回数、実施日数、数値合計を区別する             | 暫定               |
| 欠損     | 数値未入力をゼロとみなさない                       | 暫定               |
| 週N回    | 同日2回を「2日」とみなさず、異なる実施日を数える   | 暫定               |
| 記録帰属 | 原則、開始日のローカル日付に紐づける               | 暫定／睡眠は要決定 |
| 履歴     | 目標・周期変更で過去実績を不用意に再解釈しない     | 必要条件           |
| AI保存   | 提案生成時点ではNotionに書き込まず承認後に保存     | 決定               |

# 6. MVPスコープと段階

| 段階    | 対象                                                   | 完了基準（案）               |
|---------|--------------------------------------------------------|------------------------------|
| Phase 0 | Workers上のNestJS、Notion接続、Mastra／Workers AIのPoC | 各最小処理が成立し制約が判明 |

| A2      | 実施記録、数値、日次集計、スキップ／延期、履歴         | APIだけで日常実績を扱える    |

# 9. 特に注意する設計上の不整合

- 以前の設計ではExecutionRecordに「Completed／Skipped／Deferred」を同居させていたが、最新案では「実施事実」と「予定への判断」を分離する。後者はまだ提案段階。

- 「Notionだけで無料で運用できる」は確定していない。API制限、OAuth情報保存、同時更新の整合性、Workers AI・検索費用は別問題。

- 最初はタスクCRUD中心だったが、現在のMVPの中心はRoutine／Occurrence／Execution。一般的な単発Todo管理はMVPの主役ではない。

- AIによる状態更新は優先方針だが、習慣の単純な完了チェックにAIを必須としない。

- WorkersとNestJS／Mastraの相互運用は未検証。特定の構成が動作保証済みとみなして設計を固定しない。
